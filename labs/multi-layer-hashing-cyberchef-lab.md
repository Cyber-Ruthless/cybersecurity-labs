# Multi-Layer Hashing with CyberChef (MD5 → SHA1 → HMAC)

A short lab exploring how chaining multiple hashing and keyed-hashing operations together in [CyberChef](https://gchq.github.io/CyberChef/) transforms a simple input into a layered, keyed digest — and why that layering matters for data integrity verification.

> ⚠️ **Disclaimer:** Performed entirely in CyberChef, a free client-side analysis tool, against sample lab data. No real secrets or production systems were involved.

---

## Lab Environment

| Component | Details |
|---|---|
| Tool | [CyberChef](https://gchq.github.io/CyberChef/) (GCHQ) |
| Input | Plaintext string: `My account number is 0234569198` |
| Recipe | `MD5` → `SHA1 (80 rounds)` → `HMAC` |

---

## Building the Recipe

A three-stage recipe was assembled in CyberChef's drag-and-drop interface:

1. **MD5** — hashes the input string first, producing a 128-bit digest.
2. **SHA1 (80 rounds)** — the MD5 output is re-hashed through SHA-1, explicitly run for 80 rounds.
3. **HMAC** — the result is then passed through an HMAC operation using a hex key (`12`) with **MD5** set as the underlying hashing function, producing the final keyed digest.

With **Auto Bake** enabled, CyberChef recalculates the output live as each operation is added or adjusted — no need to manually trigger each step.

## Why Layer Hashes Like This?

A single hash (like MD5 alone) only proves that data hasn't changed — it offers no way to verify *who* produced that hash, since anyone can recompute it. Wrapping a hash chain in an **HMAC** step adds a shared secret key into the computation, so the final digest can only be reproduced by someone who also holds that key. In other words:

- **Plain hashing** (MD5/SHA1 alone) → integrity check only.
- **HMAC** → integrity **and** authenticity — proof the digest was generated by someone holding the correct key, not just anyone recomputing the hash.

Chaining weaker/legacy hashes (MD5, SHA1) under an HMAC wrapper is primarily useful here as a teaching example of **how** hash chaining and keyed hashing work mechanically in a tool like CyberChef — in real systems, HMAC should be paired with a modern hash function (e.g. **HMAC-SHA256** or stronger), since both MD5 and SHA-1 are cryptographically broken for collision resistance and shouldn't be relied on for security-critical integrity checks.

---

## Key Takeaways

- **CyberChef** is a fast way to prototype and visualize hashing/encoding pipelines without writing any code.
- **HMAC vs. plain hashing** — HMAC introduces a shared secret, turning a simple integrity check into an authenticated one.
- **Algorithm choice still matters** — chaining operations doesn't rehabilitate broken hash functions; use strong, modern primitives (SHA-256/SHA-3) in any real HMAC implementation.
